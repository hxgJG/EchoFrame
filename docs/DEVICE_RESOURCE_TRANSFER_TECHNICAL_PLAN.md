# 设备互传技术方案与实施门槛

核对日期：2026-09-26。状态：**App 内互传全链路已接入，进入本机安装和双设备手动验收；当前实现与验证结果以第 9 节为准。第 1–8 节保留设计取舍与首批开发记录，不代表当前代码仍缺失网络或 UI。**

产品约定以 [设备间资源传输需求](DEVICE_RESOURCE_TRANSFER_REQUIREMENTS.md) 为准。本文件记录当前仓库约束、官方文档结论、推荐技术方向及必须通过的原型门槛，不将文档示例当作可直接发布的安全实现。

## 1. 首版基线

- 局域网，无账号/云服务，macOS 与 Android 双向及同平台互传。
- A 选择范围后开启；B 发起连接，A 核对 B 设备码后批准一次；批准前不返回媒体目录。
- 默认授权 1 小时，可选 5 分钟至 24 小时；期间 B 自由选取范围内资源，过期/撤销后停止读取。
- 单对端、最多两个并行文件；音乐、视频、歌词、展示信息和可选封面。
- 首版保证两端前台传输，所有操作在 App 内；无需独立 Web 管理页、浏览器下载或后台常驻服务。
- 文件放 App 管理的持久“已接收”目录，自动入库并提供另行导出；歌词/展示信息覆盖分别可选。

## 2. 官方资料核对结论

### 2.1 macOS：沙盒网络权限与局域网隐私是两件事

沙盒应用监听入站连接需要 `com.apple.security.network.server`；双向角色还需现有客户端权限。本仓库 DebugProfile 已包含服务端权限，Release 尚缺，不能只验证 Debug。来源：[Apple 服务端网络权限](https://developer.apple.com/documentation/BundleResources/Entitlements/com.apple.security.network.server)。

macOS 15 起另有局域网隐私授权。应声明本地网络用途及特定 Bonjour 服务类型，用户拒绝后给出可恢复提示。Apple 还明确指出本地网络授权的身份跟踪依赖代码签名，并建议使用 Apple 签发的签名身份。终端启动的命令行程序存在权限例外，故命令行连通不能替代正常 App 启动验收。来源：[Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy?changes=__3)。

项目决策：不修改系统全局隐私设置，不关闭防火墙，不以 root/Terminal 启动绕过授权。当前本机采用临时签名，后续必须检查正常安装启动的权限表现；正式发布的证书、公证与稳定权限身份是交付前环境条件。资料核对不代表已有证书可用。

### 2.2 Android：按目标 SDK 分层，不盲目加新权限

当前 `android/app/build.gradle` 使用 Flutter 的 target SDK；本机 FlutterExtension 值为 36。官方规则是 Android 16 的局域网限制为可选测试；Android 17 对 target SDK 37+ 强制使用新的局域网权限机制。target 36 或更低时，官方明确不要提前声明/请求 `ACCESS_LOCAL_NETWORK`。项目应保留权限适配层，在升级 target 37 时一起处理双向连接与拒绝/撤销。来源：[Android 局域网权限](https://developer.android.com/privacy-and-security/local-network-permission)。

不因本需求擅自升级 SDK、扩大蓝牙/定位权限或增加后台服务。不能认为内嵌网页或 Dart socket 会绕过操作系统网络限制。

### 2.3 发现：采用系统 DNS-SD，发现信息不构成信任

Android NSD 使用 DNS-SD，支持服务注册和发现，端口可以由系统分配；服务名可能因冲突被调整。macOS 侧采用系统 Bonjour 对应实现，不手写全网广播探测。来源：[Android NSD](https://developer.android.com/develop/connectivity/wifi/use-nsd)。

这是跨平台局域网互通的推荐路线，不使用仅 Apple 设备之间可用的 Apple peer-to-peer Wi-Fi 作为 Android 链路。来源：[Apple 网络 API 选择](https://developer.apple.com/documentation/technotes/tn3151-choosing-the-right-networking-api?changes=__8)。

### 2.4 Dart/Flutter：有 HTTPS 与流式基础，但不等于完成安全配对

`HttpServer.bindSecure` 支持安全监听、动态端口和请求客户端证书；`File.openRead` 可提供指定区间的文件流。这支持优先验证共享 Dart 传输层的可行性，但不保证 Android Content URI、平台私钥或 Range 协议能直接无缝复用。来源：[Dart 安全监听](https://api.dart.dev/dart-io/HttpServer/bindSecure.html)、[文件流](https://api.dart.dev/dart-io/File/openRead.html)。

`badCertificateCallback` 可以决定是否接受验证失败的证书，因此不能设置为无条件 `true`。仅可按经认证的对端身份作精确校验，发现广播中的指纹不是可信引导信息。来源：[Dart 证书回调](https://api.dart.dev/dart-io/HttpClient/badCertificateCallback.html)。

平台通道适合调用原生能力和传送状态，但会编码消息。项目因此把大文件读取设计为原生流或有背压的有界分块，不用单次 `Uint8List` 把整部视频搬到 Flutter。来源：[Flutter 平台通道](https://docs.flutter.dev/platform-integration/platform-channels)。

### 2.5 存储与系统备份

Android 应用专属文件会随卸载删除，内部持久目录与缓存目录语义不同；已接收的正式文件不放缓存。来源：[Android 应用专属存储](https://developer.android.com/training/data-storage/app-specific)。

Android 默认系统备份可能包含应用文件，需显式排除传输状态、身份材料及大文件。`noBackupFilesDir` 可用于本功能私有持久区域；若使用普通 files 目录则需分别配置适用系统版本的备份规则，不能仅依靠 `allowBackup=false` 推断所有厂商的设备迁移行为。来源：[Android Auto Backup](https://developer.android.com/identity/data/autobackup)。

macOS 的受管理文件可放沙盒 Application Support；临时下载状态/可再生成缓存采用明确的备份排除标记，不能认为沙盒文件天然不会被系统备份。正式接收文件的系统备份策略与 App 内手动备份分开处理，不静默改变用户现有整机备份习惯。来源：[Apple 文件存储指导](https://developer.apple.com/documentation/foundation/using-the-file-system-effectively?changes=l_3)。

### 2.6 密钥与短码配对

设备长期身份密钥优先由 Android Keystore / macOS Keychain 管理。尤其 Android Keystore 密钥可以不可导出，不能假设可导出 PEM 后直接交给 Dart `SecurityContext`。身份签名、传输层临时证书与安全存储之间的桥接必须原型验证。来源：[Android Keystore](https://developer.android.com/privacy-and-security/keystore)、[Apple Keychain](https://developer.apple.com/documentation/security/keychain-services)。

SPAKE2 是有公开协议和测试向量的口令认证密钥交换参考，可以用于评估短码配对；规范存在不等于本仓库已有可用且经过审查的库。本期不抄规范自行实现密码学。来源：[RFC 9382](https://www.rfc-editor.org/rfc/rfc9382.html)。

## 3. 推荐架构与原型取舍

### 3.1 固定职责，不提前锁死未验证依赖

| 层 | 职责 | 约束 |
| --- | --- | --- |
| Flutter 页面 | 开启、连接、A 审批、目录、任务、冲突与导出 | 复用现有主题；只有可信本机页面能批准；不增加网页端 |
| TransferController / 领域层 | 会话、授权范围、到期、任务状态机、去重、重试 | 不依赖播放队列，不把全部网络逻辑加入 `app_state.dart` |
| PlatformDiscovery | Bonjour / Android NSD、接口变化 | 只在主动操作期间工作；手动地址只代替发现，不替代认证 |
| PeerIdentity / Pairing | 身份、短码/二维码认证、对端绑定 | 使用成熟库/平台能力；引导认证完成前不放行资源 |
| SecureTransport | 控制请求和带背压的数据流 | 优先验证 Dart HTTPS；若密钥/文件句柄不可安全桥接，改用原生传输适配，不能降低认证标准 |
| ResourceResolver | 索引 ID → 授权本地文件/歌词/附件 | 不接受对端路径，检查可见性、权限、版本和实际文件身份 |
| ReceivedMediaRepository | 持久文件、独立索引、恢复、导出 | 接收后既能播放，也能重新作为发送资源 |

主候选为 Flutter/Dart 共用控制逻辑 + 原生发现/身份/文件适配。全原生传输是文件流或密钥桥接不通过时的技术备选；两者不改变用户体验与产品范围。

### 3.2 连接和配对的实现门槛

1. 发现/手动输入只得到候选地址，绝不直接信任对端身份；广播不携带安全码、令牌或目录。
2. 首版必须保留“输入 A 连接码”的路径。评估成熟 PAKE 或其他经过审查的认证引导方案，并用标准向量、错误码、冒充/中间人场景验证；二维码只能作为辅助，不能悄悄替换掉手动码功能。
3. 若二维码携带可信证书指纹/高熵邀请材料，只能来自 A 本机实际展示；通过未认证网络取得的相同数据不具备同样信任。
4. 认证握手需绑定实际设备公钥、会话、双方随机数和传输端点。完成密钥确认后才显示可批准的 B 身份；设备名、IP、自报短码都不能替代此绑定。
5. A 批准后创建本机只读授权。凭据绑定被认证的 B 及作用域，后续请求要有设备私钥持有证明或绑定到已认证连接，不能只用可任意转交的裸 Bearer 字符串。
6. 反向共享需要另一份授权；共享通道或复用发现不代表互相自动开放。

**发布阻断条件：** 尚未选定可审查的配对实现、允许任意证书、凭据不能绑定对端、短码可被离线穷举而无保护、授权绕过测试失败。不能以“同一 Wi‑Fi 很安全”为理由先开放真实媒体再补认证。

### 3.3 网络生命周期

- 服务类型原型可用专用 DNS-SD 名称；公开发布前核对命名/注册要求。使用系统动态端口，不抢固定端口。
- 只绑定用户当前允许的本地网络接口；校验候选目标/来访来源及实际接口，不默认同时开放 VPN、公网或所有网卡。IPv4/IPv6、热点及接口切换纳入验证，不硬编码网卡名。
- 无活动共享/接收流程时不启动发现；关闭共享停止监听和广播、使授权失效、关闭文件流。
- 超时按提供方单调时间计算，并考虑睡眠恢复；展示时间用本地墙上时钟换算。授权不持久化恢复，进程重启必须重新批准。
- 手机后台/锁屏导致暂停时保存任务检查点；授权继续计时，返回前台重新校验，不能静默延长有效期。
- 系统授权弹窗/文件选择器短暂覆盖 App 不应被误判为用户永久关闭传输；生命周期适配需实测。

## 4. 接收文件与现有工程的接点

### 4.1 持久位置与索引

- Android 主候选：应用内部 `noBackupFilesDir/lumio_transfer/received`，临时块及任务日志在同级独立目录；这是本功能设计选择，不是依赖可回收缓存。
- macOS 主候选：用系统 API 获取沙盒 Application Support，再建立 `Lumio/received_media` 和任务目录；不硬编码 `/Users/...` 或容器绝对路径。
- 界面将该来源显示为“已接收”，支持查看占用和显式导出。Android 导出通过系统选择的目标流，macOS 通过保存面板；只处理用户选定资源，不静默公开整个目录。
- 文件名由本机生成的资源 ID 和经过允许列表验证的扩展名组成；对端标题只用于显示，不能拼成目标路径。
- 原型验证 `transfer-<uuid>` 一类独立本地 ID，增加明确来源标记与相对文件引用，不把对端 ID 冒充本地 MediaStore ID。

### 4.2 必须修改的现有行为接点

当前 `_applyScanResult` 用新扫描列表替换音视频列表。必须改成按来源合并：保留合法“已接收”索引，同时更新系统扫描来源，继续尊重隐藏规则。不能通过“接收后触发一次全盘扫描”替代独立索引。

Android `mediaStoreUri` 通过媒体 ID 的数字后缀构造 URI；这不适用于私有接收文件。新增来源解析器，保留既有 MediaStore 路径，另行支持受管理文件流、播放和重新分享；系统导出不强行伪造 MediaStore 记录。

macOS 现有书签存取主要针对用户授权文件夹；App 自有“已接收”目录需要专用解析分支，不能让任意路径因位于沙盒就自动变成可共享资源。

歌词接收复用现有解析/匹配/历史语义，但需要从经过验证的资源描述构造导入数据；不通过 UI 文件选择器中转。下载完成前用户有本地修改时，按版本签名提示冲突，不能静默覆盖。

### 4.3 保存与恢复顺序

`记录任务 → 流式写部分文件 → 校验长度/完整 SHA-256 → 发布正式文件 → 提交接收索引与媒体信息 → 回执`。

- 同一文件系统内优先使用原子重命名；文件提交与索引并非一个数据库事务，必须有可恢复任务日志。
- 每个阶段可重复执行：校验成功的文件不重复下载，回执丢失不重复入库，崩溃后只处理自己记录的临时/待入库文件。
- 新建文件和替换歌词/元数据分别记录结果。日志写入失败不能显示成功；不能沿用吞掉错误的普通自动保存接口。
- 任务目录有版本、大小和数量限制；未知版本保留并禁止破坏性写回。现有 App 备份不自动装入媒体二进制或设备身份；恢复到另一设备时不能恢复原设备访问令牌或文件绝对路径。
- 不默认引入数据库；先采用独立原子元数据文件/分区，避免每个下载进度事件重写完整媒体库。

## 5. 传输契约草案

以下为逻辑契约，实际路由/消息编码在原型定型后冻结，不使用共享文件系统路径作为 API。

| 阶段 | 输入/输出 | 强制检查 |
| --- | --- | --- |
| 协议协商与连接申请 | 版本、能力、认证引导消息 | 长度/频率上限；未授权不返回目录；版本不符不降级到明文 |
| A 本机批准 | B 的认证身份、资源集合、附件策略、5 分钟～24 小时 | 只由本机界面发起，不能由对端请求替 A 自动执行 |
| 目录分页 | 会话凭据、游标、筛选 | 当前作用域与可读性，移除项不可通过缓存游标继续读取 |
| 创建下载任务 | 幂等任务 ID、资源版本、附件列表 | 所有资源在会话范围内，不触发第二次审批 |
| 读取文件区间 | 资源 ID、期望版本、偏移和长度 | 64 位边界、单次上限、限流、有效授权、源身份及版本 |
| 完成/失败回执 | 任务 ID、资源结果、摘要 | 幂等更新，仅记录该 B 的任务 |
| 续期/撤销/关闭 | 本机操作、目标会话 | 续期必须重新批准；撤销停止现有数据流，不仅禁止新请求 |

若采用 HTTP Range，应显式实现单区间解析、响应长度、版本条件和越界错误，不假设文件流 API 自动提供完整续传语义。每个块/有界发送周期检查到期与撤销，不能一次批准后放任长流持续到过期。

完整文件 SHA-256 用于校验/去重；当前歌词哈希的 512 MiB 上限不适用于互传。源内容发生变化则使旧任务失效或使用已冻结内容，不拼接不同版本。媒体大文件不强制打包 ZIP，避免提供端先复制整部视频；歌词可继续使用受限清单/歌词包格式。

## 6. 实施顺序与验收门槛

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0 技术原型 | 正常 App 启动下的发现/权限、认证配对、文件流、接收文件播放样例 | 两个平台均验证；选择可用配对库及安全存储桥接；拒绝授权时没有资源泄露 |
| P1 单文件闭环 | App 内开启、审批、浏览、下载、校验、入库、导出、重新分享 | macOS/Android 双向完成；重启/扫描后文件不消失；到期/撤销立即限制后续读取 |
| P2 完整资源规则 | 批量、封面、歌词、名称同步、待匹配、去重、冲突与续传 | 已有歌词迁移行为保持一致；重复与中断任务可恢复，不覆盖后续编辑 |
| P3 真机和发布验证 | 四种有向平台组合及权限/空间/大文件/异常矩阵 | 无未解释的部分成功或授权旁路；正常签名安装路径通过，不以终端进程替代 |

P0 使用合成文件，不未经选择就开放用户媒体。必须验证错误连接码、伪造设备、错误证书、重放旧授权、越界资源、被修改的内容、5 分钟时限和模拟过期、超过 512 MiB 的视频、磁盘满、强制退出恢复。

已有静态检查与测试继续复用；按项目约定不默认新增 UI 单元测试。协议、解析器、授权与持久化可添加有针对性的核心验收，外加两台设备真实传输，不能只依据构建成功交付。

## 7. 开始实施时的结论（历史记录）

产品层已无必须再次询问用户的分支，用户已明确启动实施。技术上仍需验证短码认证实现、平台密钥桥接、正常 App 权限与跨来源文件适配，这些是实施门槛，不是需要用户选择的算法题。

当前未更改网络权限、未开端口、未部署服务器、未传输用户媒体、未安装、未提交或 push。若原型发现需要证书配置、新的安全敏感授权或明显改变用户已确认体验，再说明具体原因请求决定；不绕过平台保护。

### 必须明确的边界

- `TransferPeerBinding` 是未来安全适配器提供的**进程内认证结果契约**，不是网络身份验证实现。测试中的构造值只用于合成测试，不能从网络 JSON 直接构造并放行。当前没有真实连接码、设备密钥、TLS、发现广播或网络端点。
- `TransferResourceReader` 尚无真实媒体读取实现。后续必须以原生受控句柄绑定已选索引、权限、可见性、文件身份和内容版本，不能把对方路径直接交给文件 API。
- `ready` 只表示接收字节已验证和保存，**不表示已入媒体库**。持久媒体索引提交后才能 `markIndexed`；`baseVersion` 和两个覆盖选项随任务保存，但歌词合并/版本冲突决策还未接入。未入库日志不能清除，清除已入库历史不删除正式媒体。
- 当前去重只覆盖保留的接收记录；全库查重、独立已接收索引、扫描合并、Android 私有文件播放/导出/重新分享、待匹配歌词均待 P1/P2 接入。
- 单机接收核心与提供核心分别限制两项并发；双向共享同一个总预算、跨进程独占、系统生命周期暂停需要在 App 控制器阶段接入。存储对象须由同一控制器独占，不允许多个进程同时写同一目录。
- 不在生产界面加入只能点击而不能传输的入口，不通过关闭证书校验或明文服务完成演示；安全配对门槛保持不变。

### 配对依赖核查

本轮核查的 Dart [`spake2plus`](https://pub.dev/packages/spake2plus) 仅声明 Linux/macOS 支持，依赖 OpenSSL 3 动态库；不能直接当作已支持 Android 的 Flutter 依赖。RustCrypto [`spake2`](https://docs.rs/spake2/latest/spake2/) 明确说明尚无独立第三方安全审计，且仍需通道绑定及密钥确认。两者均未被本项目引入或宣布通过安全审查。下一步需完成跨平台实现选型、构建/标准向量验证及安全引导评审；不能因核心读写已实现而跳过。

## 9. 当前实现与交付验收（2026-09-26）

### 9.1 可操作入口

设置 → **设备互传**，包含“提供资源 / 接收资源 / 已接收”三个 App 内页面。界面沿用现有主题、字体和 Material 控件；未新增外部网页、账号或云服务。

- 提供方按音乐、视频、歌词筛选、多选或全选，最多 500 项。音乐可附带正式歌词、媒体可附带封面；默认不共享任何资源。
- 选择本地网络地址后开启。接收方复制粘贴连接码申请，提供方核对接收方设备安全码后批准。时长选项 5 分钟到 24 小时，默认 1 小时；可立即撤销或停止共享。
- 批准前不提供目录；批准后接收方自由选取范围内资源，查看大小与覆盖选项后开始接收。
- 接收进度、速度、各项结果、暂停、同来源重新选择后的断点继续、取消未完成分块、已保存文件重新确认入库均在 App 内。
- 音视频入库后可正常使用既有播放入口，并在重启或重新扫描后保留。歌词进入既有歌词库，可先保存、之后按指纹/别名关联新添加的歌曲。
- “覆盖歌词”“同步歌名/艺术家/专辑”独立可选；已有歌词历史及原始名称匹配规则复用。接收期间本地内容变化则保留接收文件并要求重新确认，不静默覆盖。
- 已接收音视频可以另存；音乐库/视频菜单也有“另存接收文件”，不会因为历史记录清理而失去导出入口。Android 私有媒体通过限定目录的 FileProvider 分享，只授予用户所选 URI 的临时只读权限。

### 9.2 认证引导的具体实现

当前采用**可复制粘贴的长连接码**，不是可口述的短数字口令。已向用户说明这一取舍；未把短码认证库声明为已实现或已通过审计。

`LUMIO1-…` 包含提供方本地地址、动态端口、证书 SHA-256、共享会话及 128 位随机邀请材料。仅在提供方 App 内显式复制，不出现在发现广播中；新申请有效期 10 分钟，刷新立即使旧邀请对新申请失效。输入路径仍保留，但本版本没有扫码功能或短数字码 PAKE。

底层使用 Dart `SecureSocket/SecureServerSocket` 标准 TLS（最低 TLS 1.2），精确固定连接码中的证书摘要，同时检查证书有效期，不接受任意证书。B 在固定到 A 的 TLS 内用持久 RSA-2048 设备身份对双方随机数、会话、A 证书、B 公钥及名称作 SHA-256/RSA 签名；A 验证持钥证明后才创建本地审批。后续每次重连重新证明持钥；已批准身份重连不延长授权期限。设备名不是身份凭据。

这是基于标准 TLS、签名与带外指纹引导的应用协议，**不等同于独立第三方安全审计**。长连接码须通过用户可信的渠道交给 B；若连接码被替换，不能靠附近发现结果推断对端可信。最终双方仍应核对设备安全码。

macOS 身份放 Keychain；Android 使用 Android Keystore 的不可导出 AES-GCM 包装密钥加密持久身份文件，密文位于 noBackupFilesDir。RSA 身份本身会在当前进程内解密使用，不能宣传为“RSA 私钥永不离开硬件”。身份不进入普通媒体备份。

依赖锁定为 `basic_utils 5.7.0`（保持现有 archive 3 兼容）和 `nsd 4.1.0`（兼容项目 Dart 3.9），未为本功能升级 Flutter SDK 或歌词包 ZIP 依赖。

### 9.3 文件、权限与生命周期

- 发送端完整流式 SHA-256，加每 256 KiB 分块摘要；通过原生受控句柄再次核对内容，避免共享期间原文件变化拼出错误内容。不复制整部来源视频，也不将整部视频送入 Dart 内存。
- 当前原生单文件上限 **64 GiB**（分块摘要表有界）；歌词/封面缓存合计最多 128 MiB，封面最多 10 MiB。协议元数据清单最多 1 MiB。
- macOS 保持书签访问作用域，检查真实目录边界、普通文件、符号链接与本地可读性；Android 分开处理 MediaStore 和私有接收文件。对端只能请求已经解析的随机资源 ID，不能传入本机路径或任意 URL。
- 网络接收先写部分文件和原子日志，完整摘要一致后才进入 received；“文件已校验”与“持久索引已保存”分开。使用私有来源索引及相对文件名，启动时按当前设备路径重新定位。
- 全库同种类、同大小候选完整哈希查重；不以名称判重。已验证的相同接收内容可复用，同名不同内容保留不同文件。
- 原生进程锁阻止两个 App 进程同时运行互传写入。单 App 控制器持有接收仓库；最多一个对端，双向分别授权；当前调度单发送读通道 + 单接收队列，总计不超过两个在途文件。
- App 隐藏/后台时暂停接收、断开数据连接、停止发现与广播；返回前台可重连，有效期不顺延。局域网接口/地址变化会关闭共享并要求重新开启。相同接口/相同地址下的热点漫游仍应纳入真机验收。
- Release 已添加 macOS 服务端网络 entitlement、Bonjour 声明及用途说明；Android 添加发现所需权限。未关闭沙盒，未配置端口映射或系统级安全例外。
- 已接收正式文件不会随任务历史清理删除。未完成分块保留 24 小时，已完成历史至多 200 项 / 30 天；歌词在既有歌词库导出为 LRC 或歌词包。

### 9.5 用户手动验收步骤

1. 两端安装同版本，连接同一局域网并保持前台。在 A 的设置 → 设备互传 → 提供资源选择一首音乐（附歌词/封面）和一个视频，开启共享。
2. 复制 A 连接码，在 B 的“接收资源”中粘贴。A 核对 B 屏幕显示的设备安全码，先拒绝一次，再重新申请并授权 5 分钟。
3. B 勾选下载，确认两个覆盖选项。检查播放、歌词、展示信息、封面；重启并重新扫描后再次检查。
4. 同一文件再次选择应跳过下载；同名不同内容不覆盖。单独先接收一首不存在歌曲的歌词，之后加入对应歌曲，应正确关联。
5. 大文件途中暂停/断网/切后台，返回前台重连同来源并重选，检查断点继续；A 撤销或到期后 B 不得继续获取新数据。反向传输要由 B 另行开启并批准。
6. 在“已接收”或媒体菜单另存文件；检查导出文件可被其他播放器读取。若提示局域网权限/防火墙问题，在系统设置恢复权限后重新开启共享，不关闭系统防护。
