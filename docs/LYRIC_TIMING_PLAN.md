# 桌面端歌词时间校准方案

状态：首版已实现。下方保留设计依据；使用说明和验证结果见本节。

## 首版落地

- macOS 播放详情页右上角「校准歌词」打开校准面板；桌面歌词未锁定时右键选择同名菜单也可打开，并激活主窗口。
- 默认仅当前歌曲；支持 0.1 秒细调、0.5 秒快调、±30 秒范围、整数毫秒输入（回车预览）和选句「此句从现在开始」。面板内可以暂停/继续播放。
- 调整实时同步详情与桌面歌词；「保存」才写入媒体库，「取消」不落盘，「恢复本曲默认」先预览零偏移，仍需保存确认。既有全局偏移保留并在面板标明。
- 歌词区域/校准面板/桌面歌词启用时，播放中的歌词以约 100ms 查询实际媒体位置，通过局部通知刷新；主应用仍保留既有低频刷新。原生悬浮窗继续仅发送有变化的文本/状态。
- 偏移以版本化 `lyricTiming` 保存，旧库默认零；同歌词重扫保留、更换歌词清除。切歌、重新导入或移除歌词使草稿失效，已打开的面板提示关闭后重新校准。
- 已核查原生存储及元数据修复保留媒体记录的附加字段，备份沿用完整媒体记录，不需要另建数据库或修改原始文件。
- 验证：Flutter 静态检查通过；已有 28 项测试通过；临时模型/状态校验通过旧数据兼容、序列化、方向/边界、保存/取消、失败回退、全局偏移叠加、重扫及切歌竞态；macOS Release 构建通过。
- 尚未覆盖已安装应用，尚未进行真实音频听感与右键菜单的真机交互验收。双点、逐行编辑及 LRC 内置 offset 解析不在本次首版范围。

## 目标与边界

解决用户播放音乐时歌词整体提前或滞后的问题：在播放详情页边听边调，仅影响当前歌曲，详情页与桌面悬浮歌词同时生效，重启后保留。

首版不修改音频、不改变播放速度、不覆盖原始 LRC 文件，不提供逐字卡拉 OK、自动识别人声或完整歌词编辑器。音频版本不一致、删节、插入间奏等不能靠一个偏移值解决。

## 实施前现状链路

- `lib/core/lyrics/lrc_parser.dart` 将 LRC 时间标签解析为毫秒级 `LyricLine` 并排序；目前不读取 `[offset:...]` 元数据。
- `MediaItem.lyrics` 保存解析后的歌词，随媒体库索引持久化；模型没有单曲校准字段。
- 设置页已有全局「歌词偏移」，步长 500ms、范围 ±10 秒，保存在 `LumioSettings.lyricOffset`，会作用于所有歌曲。
- `AppState.currentLyricIndex` 使用「播放位置 + 全局偏移」查找当前句。正值意味着歌词提前显示，负值意味着延后显示。
- 播放详情页与原生桌面歌词共用这个索引；后者通过 `lumio/desktop_lyrics` 接收当前句和下一句，已有去重发送逻辑。
- 当前播放位置每 700ms 查询一次；macOS 底层返回 `AVPlayer.currentTime()`。即使保存到毫秒，当前刷新粒度也不适合细调体验。
- 重新扫描按媒体路径合并历史信息，手动导入歌词优先保留；新增校准数据必须接入此合并流程。

## 方案比较

| 方案 | 收益 | 局限 |
| --- | --- | --- |
| 将现有全局偏移移到播放页 | 改动少，适合统一设备延迟 | 调一首会影响其他歌曲，不宜作为默认方式 |
| 单曲偏移 + 实时预览（推荐首版） | 复用现有时间轴，满足整体错位，成本可控 | 不能纠正逐渐累积的节奏误差 |
| 双点/逐行时间编辑器 | 可处理部分漂移和局部错位 | 交互、撤销、排序及数据兼容复杂，后续独立迭代 |

## 首版交互

1. 在播放详情的歌词区提供「校准歌词」，打开非阻塞小面板，音乐继续播放。
2. 默认作用域明确标为「仅此歌曲」，显示歌曲名称及「歌词提前 0.3 秒」等自然语言，不只显示正负号。
3. 提供「提前 0.1 秒」「延后 0.1 秒」；可选 0.5 秒快速步长和数值输入。建议单曲范围 ±30 秒，越界禁用或提示，不静默截断输入。
4. 按钮提示明确：歌词比人声晚出现 → 提前；歌词比人声早出现 → 延后。调整不 seek 音频、不重播。
5. 「恢复本曲默认」「取消」「保存」：调整先实时预览，保存后持久化，取消恢复打开前的本曲校准。重置不清除已有全局偏移，面板同时标明全局偏移是否参与。
6. 校准模式可选中一句歌词，再按「此句从现在开始」自动计算整体偏移。普通歌词区点击行为不因此改变；当前句滚动不抢走用户正在选择的行。
7. 桌面悬浮歌词不增高、不加常驻控制行；通过未锁定时的菜单「校准歌词」唤起主窗口同一面板。锁定时仍从主 App 操作，保持鼠标穿透。
8. 没有有效时间标签的歌词不提供校准，提示先导入带时间标签的 LRC。

## 数据与时间轴

建议为 `MediaItem` 增加可选结构，旧数据缺省视为零偏移：

```json
{
  "lyricTiming": {
    "version": 1,
    "offsetMs": 0,
    "lyricsSignature": "当前时间标签与歌词文本的稳定摘要"
  }
}
```

- `offsetMs` 延续现有符号：正值提前，负值延后。版本字段为后续高级校准保留迁移入口，不在首版引入多套未使用的算法。
- 歌词比较时间 = 音频位置 + 现有全局偏移 + 本曲偏移（编辑时使用本曲草稿值）。详情页和悬浮窗只读取这一处结果，不在 Swift 内另算偏移。
- 若选中句的时间为 L、点击时音频位置为 P、全局偏移为 G，则本曲新偏移为 `L - P - G`，不要叠加旧本曲偏移。超出范围时提示人工确认，不自动跳转音频。
- 偏移只改变时间查询，不逐次重写歌词时间标签，避免来回调整产生累计误差。时间早于首句显示等待，晚于末句保持既有行为。
- 原始媒体和 LRC 不覆盖；校准随媒体库索引保存。相同路径、相同歌词重新扫描时保留；更换/删除歌词时清除旧校准并提示。稳定摘要用于识别扫描得到的歌词是否已改变。
- 同一路径上的音频被替换、但歌词未变时，首版不保证自动识别，应允许重置；跨路径移动仍受现有媒体身份匹配机制限制，不另建文件指纹系统。
- 所有跨平台序列化、原生读取/修复、备份恢复流程需核对并保留新字段，不能只修改 Flutter 模型后就假定字段不会丢失。
- 首版保持现有 LRC 解析语义；`[offset:...]` 支持作为后续解析兼容项单独处理，确定符号与既有校准迁移后再接入，避免双重偏移。

## 关键技术与风险控制

### 播放时钟与刷新

- 使用播放器实际媒体时间，不以普通定时器累加值作为音频时钟。暂停、seek、切歌、倍速变化后以播放器结果重新同步。
- 建议播放中且歌词可见（主窗口或悬浮窗任一可见）时将相关时间更新目标缩短到约 100ms；其他场景保留低频更新。100ms 是交互步长/刷新目标，不承诺采样级音画同步。
- 位置查询设置单请求在途保护；切歌/seek 使用播放会话序号丢弃过期返回，防止旧结果覆盖新位置。
- 「此句从现在开始」需要新鲜播放位置；读取失败时保留草稿并提示重试，不使用明显过期位置直接保存。
- 避免每次时间更新重建全应用：先度量，必要时将歌词/进度通知局部化。原生歌词仍只在句子或状态变化时发送，保留当前去重策略。

### 编辑、保存与并发

- 面板绑定打开时的 `mediaId` 和歌词版本/摘要，不隐式追随当前歌曲。切歌或歌词被替换时取消未保存草稿并提示，不能把上一首的操作应用到下一首。
- 草稿仅在内存中预览；保存时再次校验目标并只更新校准字段，不用打开面板时的整份旧对象覆盖媒体信息。
- 一次保存写入媒体库分区；不要每按一次按钮或拖动一次就写整库。写入失败明确提示，不声称已保存；取消不回滚无关设置。
- 桌面菜单新增回调可采用 `openLyricCalibration({mediaId})`，Flutter 校验仍为当前音频后激活主窗口打开面板。共享通道不传入文件路径，不接收任意执行指令。
- 不新增联网、付费服务、辅助功能或屏幕录制权限；离线工作。

## 影响模块与实施顺序

1. `lib/core/models/media_item.dart`：校准结构、默认值、序列化与 `copyWith`。
2. `lib/app/app_state.dart`：预览/保存入口、统一时间轴、重新扫描/导入合并、位置更新的过期响应保护。
3. `lib/features/music/now_playing_page.dart`：校准入口、小面板、选句对齐与自动滚动协调。
4. `lib/features/settings/settings_page.dart`：现有入口明确标注「全局歌词偏移」，保留原值和默认行为。
5. `lib/platform/desktop_lyrics/desktop_lyrics_controller.dart` 与 `macos/Runner/Platform/LumioDesktopLyricsPlugin.swift`：悬浮窗菜单及主窗口跳转，维持尺寸/锁定行为。
6. 媒体存储、原生桥接和备份恢复：核查新字段往返保留，再做构建和真机验收。

首版 UI 以 macOS 为范围；数据模型跨平台兼容。手机端若读取带校准数据的媒体库可复用相同计算，但不默认增加手机校准入口，也不承诺设备间自动同步。

## 兼容与验证

- 旧媒体库、旧备份缺字段时保持原行为，现有全局偏移不清零；新版本能读取旧数据，不保证降级后旧版本再次保存仍保留新字段。
- 验证提前/延后方向、100ms/500ms 步长、范围边界、输入校验、重置、取消、保存与重启恢复。
- 验证详情页和悬浮歌词一致，暂停/继续、跳转前后、首句前、末句后以及已有全局偏移场景。
- 验证切歌、导入新歌词、扫描更新、保存失败、快速操作时不串歌、不丢失其他元数据。
- 验证同歌词重扫、备份恢复保留偏移，旧库无偏移时不改变播放；对手机端进行共享计算/数据兼容回归。
- 验证悬浮窗锁定穿透、宽度高度和播放控制无回退，播放时 CPU/通知频率没有明显增加。
- 按项目约定不默认新增前端单元测试；采用静态检查、已有测试、macOS 构建和真机人工验收，算法/存储检查按实际实现风险补充。

## 后续：越唱越不同步

先确认音频和歌词是否是相同录音版本。若误差随时间近似线性增加，可用两个锚点拟合 `歌词时间 = a × 音频时间 + b`；两个点必须时间递增且间隔足够，对异常倍率限制并提示。该变换只作用于歌词，不改变音乐速度。

若存在删节、重复段或局部时间标注错误，需要分段/逐行编辑及撤销机制，或重新导入匹配版本，不能用全局倍数强行拟合。自动音频对齐涉及额外模型、耗时和准确率评估，不列入当前计划。

- 全局偏移保留在设置作为高级选项；双点与逐行编辑后续再做。
