# 旧中文媒体标签乱码兼容

Android 和 macOS 在扫描、加载上次扫描快照、读取本地媒体库及恢复备份时，统一检查标题、歌手和专辑标签。纠正仅作用于应用索引；不修改原音频、文件名、歌词或系统媒体库。

## 识别边界

- 针对 GBK/GB18030 字节被误作 Latin-1 或 Windows-1252 文本的情况。
- 原字段需有足够异常高位字符、未包含中文，转换必须能够按原字节无损往返，结果包含至少两个中文字符且无无效字符。
- 解码后的标题或歌手还必须出现在该文件的文件名中，才允许应用本条记录的修复；正常外文与中文字段不变。
- 如文件名只有 track01、没有可佐证的中文，或字段已经出现不可逆的替换字符，则保留原样，可手动编辑；不做无依据猜测。
- 已保存的索引在读取时自动得到修正，并随原有媒体库保存流程持久化。旧备份文件保持不变，恢复时执行相同兼容处理。

## 验证

`tool/check_metadata_repair.swift` 和 `tool/MetadataRepairChecks.kt` 为独立原生检查入口，覆盖样例、正常外文、无文件名佐证、异常输入、幂等性、库读取及非元数据字段保留。两端逻辑需同步维护。Swift 可将 helper 与检查文件一起交给 swiftc；Kotlin 可将 helper 与检查文件交给 kotlinc 后运行 main。
