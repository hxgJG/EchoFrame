### 本轮落地细化

- 工作台校准直接对草稿起止时间做可撤销平移，不另存隐藏偏移；保存项目不等于应用到媒体库。需要点击“应用到媒体库”才替换正式字幕，按内容/版本摘要检查冲突。时间输入支持毫秒时间码、直接秒数以及中文输入法全角分隔符。
- 媒体库 `subtitleState` v1 当前保存 revision/origin/sourceName/visible；正式时间已折入校准，不新增独立 advanceMs。稳定句 ID 留在项目中，正式媒体保留原 `startMs/endMs/text` 兼容格式。重新扫描保护 edited 字幕；恢复同名字幕并应用后恢复 sidecar 来源语义。未知版本不允许编辑覆盖。
- 预览与导出共用 Core Image/Core Text 渲染器；暂停修改时重建预览 item 并精确 seek，避免旧帧残留。工作台独立 AVPlayer，不写音乐队列、播放历史或原视频断点；原播放器启动时暂停工作台预览。
- 桌面原视频字幕使用事件区间索引和独立通知，复用已有单 in-flight 位置查询；手机端保持原播放行为，没有工作台入口或转码插件。
- 项目存于应用 Application Support/Lumio/subtitle_projects 的独立 UUID JSON，不复制原视频。单项目 8 MiB、最多 200 项；备份总量限制 64 MiB。设置内应用备份包含项目；恢复为新 ID 项目，保留当前项目、解除媒体库绑定，跨设备需重新选视频。备份不含原视频。
- 文件选择/项目写入串行；导出使用冻结 revision，离页后可回工作台查看进度与取消。导出任务记录只用于报告中断，不能断点续编。硬字幕导出拒绝已有目标，保存面板即使确认覆盖也不能覆盖源视频或现有文件。
- 文件级授权不包含同目录字幕权限。没有已授权媒体文件夹时，“恢复同名字幕”明确提示改用“导入字幕”手动选择，不扩大为全磁盘访问。
- 支持严格 UTF-8、带 BOM 的 UTF-16；无 BOM UTF-16/旧中文编码目前提示先转码，不自动猜测。ASS/SSA 仅纯文字和时间，绘图条目报告错误。未探测成功的源仍可保留手工草稿，预览与导出须成功探测。
- 可变帧率、特殊编码、HDR、多音轨及超 4096 边长不在当前保证范围；系统导出预设不承诺固定编码参数。较大字幕超过画面 40% 时明确报错，不静默裁掉文字。

实现验证后的细化：使用兼容 macOS 13 的 Core Image 视频合成回调，在视频呈现时间上按需叠加字幕；不额外创建每句动画图层。导出临时文件放应用临时目录，避免误认为 NSSavePanel 授权了整个输出父目录；随后以排他创建方式写目标文件，拒绝覆盖。目标写入不是原子发布，取消/失败清理本次创建的同一文件，并保留项目。

## 最新确认的需求

- 保留原视频详情页入口，同时提供独立“字幕工作台”：直接选择本地视频，不要求先加入媒体库。
- 可以导入字幕，也可以从空白手动添加、修改文字和起止时间，支持整体提前/延后。
- 用户已明确选择：**只导出带字幕的视频，不提供 SRT 文件导出入口**。
- 用户已明确限制：**本功能只在桌面端开放；当前项目实现 macOS，不新增 Android/iOS 工作台入口或视频转码依赖**。其他桌面平台仅保留接口扩展空间，不属于本期交付。
- 推荐输出语义为“硬字幕”：把文字烧录到新视频画面，其他播放器无需外挂字幕即可显示，不能关闭或单独再改；原视频不修改。若实际要求可关闭的内嵌软字幕，需要另行调整方案，不能混为同一输出。
- “上传视频”在本离线应用内指系统选择本地文件，不上传服务器。网络来源不在本期范围。

## 复核结论

初稿的“外挂显示＋SRT 导出”已不能覆盖最新需求，方案改为“外挂预览/校准＋独立编辑项目＋视频转码烧录”。本节保留设计复核结论，实际实现与验证范围以上方实施进度为准。原 SRT 导出选项已由用户选择替换，不再是待确认事项。

| 初稿问题 | 修订决策 |
| --- | --- |
| 整体偏移与单句编辑叠加规则不明确，可能重复提前/延后 | 区分源时间、显示时间与编辑草稿时间，应用编辑稿时将校准归零 |
| 导入依赖已知视频时长，校准导出默认裁掉越界句子 | 结构错误阻断；时长未知或越界提示，不阻止读取。导出不按视频末尾默认裁切 |
| 建议高频刷新，但现有计时器只在播放时更新且忽略零位置 | 单独定义暂停定位、零点、seek 完成及过期查询处理；复用底层查询，不复用歌词编辑的播放中限制 |
| 承诺所有重叠句完整显示，但现有组件仅三行 | 返回有效句列表，替换截断布局；资源异常与超出显示容量要有明确降级 |
| 单视频新增多份字幕数据，没有唯一数据源与保存顺序 | 媒体库与独立项目各自只有一个正式来源，明确应用边界与写入协调 |
| “回退旧版可读”容易被理解为无损兼容 | 旧版可能在保存时丢弃新增字段；明确备份及回退限制 |
| 首期菜单包含全部编辑功能，但交付又分两步 | 基础手动添加已是明确需求，纳入第一交付；高级编辑另分期 |
| 只有已有视频入口，无法制作独立文件 | 新增工作台、视频源授权与独立项目存储，不隐式导入媒体库 |
| SRT 文件导出不等于带字幕视频 | 新增转码导出引擎、烧录样式契约、任务状态和输出安全规则 |

成功标准：可从独立入口选择未入库视频，手动添加/导入字幕并校准、保存项目后恢复，最终导出新的视频文件；成片在其他播放器中能看到正确字幕，字幕与声音同步，原视频不变。仅能导出字幕文本不算完成。

## 目标与现状

解决本地视频添加字幕、字幕整体过早/过晚、个别句子文字或时间错误，并导出带字幕成片。预览时外挂显示，导出时重新编码并烧录；内嵌软字幕轨道提取/封装、语音识别、完整 ASS 特效、视频剪辑不纳入首期。

现有链路：macOS/Android 扫描尝试读取同名 SRT、ASS/SSA；Dart 解析为 `SubtitleCue(start,end,text)`，存入 `MediaItem.subtitles`；`currentSubtitleText` 根据播放位置选择字幕，播放页叠加显示。已有字号、颜色、位置设置。ASS 仅保留纯文字与换行，不保留样式/动画。

代码核对出的约束：

- `lib/core/subtitles/srt_parser.dart`、`ass_parser.dart`：返回句子列表，部分无效数据直接跳过，没有结构化警告；SRT 时间字段尚未严格验证分钟/秒范围。
- `lib/app/app_state.dart`：字幕只取首个命中句子，结束边界为闭区间；常规播放位置轮询为 700 ms。`_syncPlaybackPosition` 在暂停时不查询，并忽略零位置；100 ms 歌词通知仅适用于音频。
- `lib/features/music/now_playing_page.dart`：普通/全屏字幕组件最多三行且省略超长内容；画中画分支只构建视频纹理，没有字幕。
- `_mergePersistedMediaMetadata` 按路径保留现有歌词等信息，未处理自定义字幕；改名/移动后重新扫描，不能据此保证字幕关联仍在。
- 媒体库是 library 分区整体保存，播放视频时还会每 30 秒保存断点。macOS 使用串行队列和原子文件写入；这不能替代应用层对过期快照的控制。Android 存储桥接还需核对底层写入返回结果是否被正确传回 Dart。
- macOS 当前基于 AVPlayer 播放，项目与 Podfile 的最低系统版本均为 macOS 13。仓库没有视频转码导出引擎，不能把现有“保存文件”桥接当作视频烧录能力。Android 现有播放依赖与入口保持不变，不为本功能添加 transformer/effect 模块。

## 方案比较

1. **macOS 原生导出引擎（推荐）**：Dart 负责项目/编辑状态，AVFoundation 负责合成与导出，字幕由原生文本渲染器按时间戳绘制。贴合已有 AVPlayer 栈，不需用户额外安装命令行转码工具；仍需原型验证动态字幕覆盖、音画同步、字体及输出格式，不能据“能播放”推导“能导出”。
2. 跨平台转码引擎：评估 FFmpeg 一类的统一处理管线，有利于一致的滤镜与格式支持，但会新增二进制分发、体积、签名、维护和许可证核对工作。不在本轮安装依赖，也不预选未经核验的 Flutter 封装。
3. 仅写入可关闭的软字幕轨道不满足本文推荐的烧录语义，播放器是否显示也不一致，不作为本次硬字幕导出的替代实现。

已获准查询公开官方资料，原生路线有明确 API 支持，最小烧录验证已通过。离线核心无需后端，首版不引入 FFmpeg/第三方转码二进制。现有 Xcode 提供所需系统框架，最低系统版本真机兼容、沙盒授权和更多实际编码器/素材能力仍要继续验证。

### Apple 官方能力与实现约束

- `AVAssetExportSession.videoComposition` 可配置视频帧合成，导出前需检查素材/预设/文件类型兼容性，不能仅把扩展名改为 MP4。[官方导出会话文档](https://developer.apple.com/documentation/avfoundation/avassetexportsession)
- `AVVideoCompositing` 支持为播放器、导出会话和图像生成器提供自定义视频合成器。推荐原型使用它按请求的 compositionTime 查询字幕，用 Core Text/Core Graphics 或 Core Image 实现有界缓存的文字叠加；具体渲染实现属工程选择，不是官方对性能的保证。[官方合成器文档](https://developer.apple.com/documentation/avfoundation/avvideocompositing)
- `AVVideoCompositionCoreAnimationTool` 也支持叠加动画层，但时间必须来自视频时间轴，而非墙钟；适合作为少量句子快速验证备选，不默认创建两万层动画承担全量字幕。[官方动画合成文档](https://developer.apple.com/documentation/avfoundation/avvideocompositioncoreanimationtool)
- 新系统异步导出可监听状态并通过任务取消。项目要覆盖 macOS 13，按 API availability 分支封装进度、完成和取消，旧系统使用兼容导出接口；不能为省适配静默提高最低系统版本。[官方异步导出文档](https://developer.apple.com/documentation/avfoundation/avassetexportsession/export(to:as:isolation:))
- 本机 SDK 的 `AVAssetExportSession.h` 明确说明 passthrough 预设会忽略 videoComposition。因此硬字幕输出必须走视频重新编码路线，不能用透传预设冒充无损烧录。编码预设不等于精确码率/编码参数控制；若产品强制要求固定编码配置，应追加 AVAssetReader/Writer 路线评估，不能伪报成片参数。

## 独立字幕工作台

### 入口与流程

- macOS 侧栏提供“字幕工作台”，视频列表页可增加快捷入口，避免必须进入已有视频详情。手机端不增加该入口；直接路由、平台方法调用也需能力检查，不能只隐藏按钮。
- 工作台首页：新建项目、最近项目、重新定位丢失的视频、删除本地项目。
- 主流程：选择本地视频 → 探测媒体信息 → 导入字幕或手动新增 → 播放校准/编辑 → 保存项目 → 选择输出位置与参数 → 导出带字幕视频。
- 原详情页“编辑/制作字幕”打开同一工作台，创建绑定 library mediaId/revision 的项目副本。只有用户点击“应用到媒体库视频”才写回正式字幕；导出成片不隐式覆盖媒体库条目，也不自动添加成片到媒体库。
- 桌面布局为视频预览＋字幕列表/编辑区＋底部播放时间与导出区域；窄窗口采用预览与列表上下布局，不意味着移动端开放。无需强制复用音乐歌词页布局。

### 本地项目与视频源

- `SubtitleProject` 使用独立 projectId，记录 schemaVersion/revision、视频源引用、源文件身份特征（授权引用、大小/修改信息、已知时长等）、字幕编辑稿、样式、导出设置和可选 libraryBinding。视频名不是唯一 ID。
- 独立项目不创建假 MediaItem、不插入播放历史/队列；视频不默认复制一份。macOS 使用文件级 security-scoped 授权引用/书签，预览和导出期间成对持有/释放访问权限。不能把路径存在等同于应用始终可读取。
- 无法恢复授权或可随机读取时，明确提示“重新选择文件”或让用户确认复制到工作缓存，先展示所需空间；不静默缓存整部视频。云盘占位文件可能触发下载，首期提示用户选择已下载到本机的文件。
- 重新打开授权失效/文件被移走时保留字幕草稿，要求重新定位视频；身份特征不一致时提示“可能不是原视频”，禁止静默套用。特征用于检测，不声称是强内容身份校验。
- 项目按文件独立原子保存，另有轻量最近项目索引，纳入版本化备份/恢复。项目备份包含字幕和设置，不默认包含原视频；跨设备恢复需要重新选视频。删除项目仅清理项目和本任务缓存，不删除源视频或用户已导出的成片。
- 工作台预览须有独立状态与生命周期。若复用当前单实例原生播放器，必须有独占播放会话协调器：进入时提示并暂停原播放，保存原队列/位置，把预览事件路由给项目；退出时释放并按会话版本恢复，默认不自动恢复出声。不能让工作台 seek 更新原歌曲断点或桌面歌词。独立原生预览实例作为备选，需要评估音频焦点/显存开销。

## 分期与交互

### A 阶段：独立制作与成片导出闭环（最新要求）

- 视频更多菜单：导入字幕、显示/隐藏字幕、字幕校准、打开字幕工作台、恢复同名字幕。工作台内只提供“保存项目”和“导出带字幕视频”，不显示 SRT 文件导出。
- 无字幕时支持从空白新增句子，编辑文字、开始/结束时间；支持点击“标记开始 / 标记结束”、增删、基本撤销/重做、自动保存与草稿恢复。这部分不能再推迟到 B 阶段，否则无法满足“手动添加字幕”。
- 导入 SRT，兼容现有 ASS/SSA 的纯文本转换；导入 ASS 时明确提示不保留特效。保留自动扫描同名字幕的能力。
- 校准面板：明确按钮“提前 0.1 秒 / 延后 0.1 秒”、大步长 0.5 秒、秒数直接输入、重置、实时预览、保存与取消；单视频保存，建议首期偏移范围 ±60 秒。
- “将这一句的开始对齐到当前画面”：用播放器实际位置计算偏移，可暂停定位后操作。
- 校准列表始终可选择任意一句，不只提供当前可见句子；否则严重错位或暂停在字幕空隙时无法对齐。超出 ±60 秒时拒绝保存并提示，不能静默钳制。
- 显示/隐藏是单视频的非破坏性开关，保存重启后保留；不删除字幕，也不影响导出。
- “恢复同名字幕”不是“隐藏字幕”：需要确认后重新读取同名字幕；没有可用文件时先提示，读取失败不删除当前自定义字幕。恢复成功重置校准并使旧编辑稿进入冲突状态，不能自动套用。
- 校准取消恢复原偏移；重新选择文件取消、导出取消均不改变字幕状态。

### B 阶段：高级编辑（另行确认）

- 在基础编辑上增加拆分/合并、批量平移、AB 循环与倍速练习、纯文本批量拆句。每句必须有开始和结束时间，不用下一句开始时间隐式代替结束时间。
- 拆分必须选择 `start < split < end` 的时间点，并分别编辑两段文字；保留第一句 ID、为第二句生成新 ID。合并取两句时间并集，提示它会覆盖原有空隙，确认后保留第一句 ID。
- A/B 均允许保存缺少时间等未完成草稿；正式应用与导出成片必须满足结构校验。未完成草稿不能影响媒体库正在播放的正式字幕。
- 双锚点拉伸校准、自动识别单独评估，不因已有歌词制作器而默认纳入高级编辑。

## 时间模型与同步

- 统一以整数毫秒保存。建议沿用歌词校准的方向约定：`advanceMs > 0` 表示提前，显示区间为 `[startMs - advanceMs, endMs - advanceMs)`；文案不要求用户理解正负号。
- 例：字幕原来 10 秒出现，需要 11 秒出现，应“延后 1 秒”，即 `advanceMs = -1000`。
- 查询时使用 `subtitleTime = mediaTime + advanceMs`；命中 `start <= subtitleTime < end`。倍速不乘除时间戳。
- 对齐操作计算 `newAdvanceMs = selectedCue.startMs - actualMediaTimeMs`，这里必须使用未偏移的正式句子时间，不能在已有偏移上再次相加。
- 媒体库正式句子时间与 `advanceMs` 分开保存。进入工作台新建编辑草稿时，将当前偏移一次性折入草稿的开始/结束时间；编辑器显示并修改“视频时间”，不再额外叠加正式偏移。应用编辑稿到媒体库时以草稿时间替换正式句子，并将 `advanceMs` 归零；取消则两者都不变。工作台里的整体提前/延后属于对草稿时间的一次可撤销批量操作，不另藏一份导出偏移。
- 折入后产生负时间的草稿标注待处理，不自动丢句。应用前要求用户确认裁切/移除或手动修正；存储草稿允许这些临时无效时间。恢复已有草稿时不再次折入偏移，需检查其基准版本。
- 只有文字错误或少量句子错位时修改单句；整体固定偏移用校准，越播越偏则需要比例校准或分段编辑，不能靠固定偏移解决。
- 可见视频字幕提供独立通知，先以 100 ms 查询实际位置，只更新字幕子树；与已有 700 ms 查询共享单一 in-flight 调度，禁止叠加无约束定时器。不可因为查询频率提高而提高媒体库保存频率。
- 暂停后停止周期刷新，但打开/调整校准、选择句子对齐、seek 完成时允许一次性读取；零秒是合法值，查询失败不能伪装为零秒。需要明确返回有效/无效查询结果，而不是盲用现有 `position()` 的空值转零行为。
- seek 时可立即按目标位置预览，完成后以播放器返回位置校正；校准“对齐当前画面”必须等待 seek 确认。现有播放器桥接若只确认发出 seek 而非完成，需补完成语义或等待稳定位置后才允许对齐。
- 查询捕获播放会话 ID、mediaId/projectId、播放 epoch、字幕文档 revision；切换视频、恢复备份、seek、AB 跳转或异步导入更新后，丢弃过期结果。暂停本身不应禁止校准查询。
- 100 ms 轮询并非帧级精度保证，极短字幕或高倍速可能被跨过。用短句、2× 和卡顿场景实测；若出现漏句或可感知延迟，阶段 A 发布前改用边界调度/原生时间通知，不靠继续增加全局 rebuild 频率补救。
- 将 `currentSubtitleText` 的单字符串选择改为有效句列表；允许重叠和相同起点，排序键为 `(startMs, sourceOrder, cueId)`，`cueId` 用于身份而非决定双语显示顺序。使用区间查询或起止事件索引，不能仅二分找到最近一条开始时间就忽略更早开始但尚未结束的句子。
- 正常场景按顺序展示各句并换行，移除无提示的三行省略。异常重叠量与长文本设置渲染上限，超限给出标识并可查看完整字幕列表；保留全部导入数据，不宣称任意数量的重叠内容都能完整放进视频区域。布局需考虑视频缩放、黑边、安全区和控制栏。

## 数据与模块

- 媒体库正式来源仍为 `MediaItem.subtitles`（未叠加整体偏移的时间）；独立项目的工作稿以 `SubtitleProject` 为唯一来源。两者不是自动双向同步，只有显式应用才从项目写回媒体库，并校验绑定版本。
- 媒体库增加版本化 `subtitleState`：`documentId`、`revision`、`origin`（sidecar/imported/edited）、`sourceName`、`contentSignature`、`advanceMs`、`visible`；自定义标志由 origin 推导。制作草稿统一放在项目存储中，记录基准 documentId/revision，避免 MediaItem 再嵌套第二份巨大草稿。字段名为推荐契约，实现前统一命名。
- 句子增加稳定 ID 与 sourceOrder；旧 `start/end/text` 数据按确定性规则补 ID，重复的同文同时间句子也必须有不同身份。内容签名包含顺序、起止时间和文本，不依赖运行时随机 hash；revision 负责并发控制，不能只比较文本签名而漏掉偏移改变。
- 导入的字幕文件不是运行所必需的外部依赖：保存规范化字幕与来源元信息，不长期依赖临时字幕 URI，也不把原文件、正式句子、多份全文历史都塞进 MediaItem。视频源与此不同，项目恢复/导出仍需可访问的视频文件。原字幕/视频文件都不被修改，不保证还原原 ASS 样式。
- 旧数据缺省偏移为 0、visible=true、无草稿。发现未支持的新 schema 版本时不能写回覆盖；进入只读/明确提示，保留原始存储供恢复。
- 扫描同一媒体且字幕内容未变时保留校准；自动同名字幕内容变更时导入新版本、重置偏移并提示，旧草稿保留为冲突稿。自定义字幕不被自动扫描替换；显式重新导入需确认替换并重置偏移，不能静默丢弃未完成草稿。
- 身份以稳定 mediaId 为主、路径为回退；不能只按文件名匹配。当前 macOS ID 与来源/相对路径有关，改名/移动会破坏这项假设：应用内文件操作需提供旧→新媒体映射以迁移字幕关联；若本期没有可靠映射，操作前提示导出备份并明确不承诺保留。外部改名/移动后的自动找回不在首期范围。
- `lib/core/subtitles/`：增强解析与错误报告、时间校准、编辑状态、SRT 序列化和验证。
- `lib/app/app_state.dart`：导入/应用/导出、独立字幕时钟、校准预览与持久化、扫描合并策略。
- `lib/features/music/now_playing_page.dart`：视频字幕入口、叠加层和校准面板；单独新增字幕编辑页。
- 新增 `lib/features/subtitle_workbench/`、项目 repository/controller、平台视频探测与视频导出 repository。首页/侧栏/视频列表增加独立入口；`PlatformCapabilities` 分开表达能否预览、编辑、导出，不以播放器能力代替编码能力。
- `lib/platform/` 新增字幕项目/视频导出协议，macOS 新增专用工作台/导出插件，并复用已有文件授权基础设施；不要把转码任务堆进媒体扫描插件，也不要修改歌词导出允许类型来承载视频输出。Android `MainActivity.kt` 不为本功能新增桥接实现。
- `importSubtitles({requestId, allowedFormats})`：返回 status、requestId、fileName、format、bytes；限制体积后通过通道传递，由 Dart 严格解码/解析及报告。`selectSubtitleVideo` 返回受授权源句柄及探测状态，不传整部视频字节；`probeSubtitleVideo(handle)` 异步获取时长、方向、编码和音轨信息。
- 调用端在文件选择前捕获目标 mediaId/projectId/documentId/revision。选择期间切换正在播放的视频不改变目标；目标已删除或字幕被替换则提示重试。原生限制同时一个文件选择器，关闭页面/应用、取消、重复回调都有明确一次完成语义。视频导出另走带 jobId 的异步任务协议。
- 不需要后端、数据库迁移脚本或新增收费服务，但需要本地 JSON schema 迁移与备份。旧版可读已有 `subtitles` 不代表无损降级：它可能在保存时丢弃新字段。上线前保留兼容备份，回退须明确校准/草稿不可用且可能丢失；不要直接用旧版继续编辑唯一的新版本库。

## 成片导出契约

- **输出目标**：新 MP4 文件，字幕烧录到视频画面，不附加可关闭字幕轨。默认命名 `<原名>_字幕版.mp4`；原视频与输出同一文件/同一 URI 时拒绝，不接受用“覆盖确认”覆盖源视频。
- **初始输出配置**：优先验证 SDR、H.264 视频＋AAC 音频；无音轨视频不添加伪音轨。保留原比例/方向，不强制横屏、不放大低分辨率内容。分辨率、帧率和编码级别受平台编码器限制，探测后给出可用选项；不能静默降清晰度、丢音轨或把 HDR 颜色处理错误。
- **明确支持边界**：首轮原型验证常见 SDR MP4/MOV、横竖屏、旋转元数据、单音轨、有/无音频、中文多行与重叠字幕。HDR、多音轨选择、可变帧率与特殊编码分别验证后开放；未验证/不支持时解释原因，不宣称所有能播放的视频均可导出。原视频已有硬字幕不会被自动去除。
- **渲染一致性**：字幕不是录制 Flutter 播放界面；原生导出按视频的呈现时间戳取句子，与预览共享时间判定和样式模型。字体大小、边距以输出画面比例定义，使用明确的字体资源/回退策略；预览控制栏、播放按钮、黑边布局不能烧进成片。渲染需按当前有效句缓存，不能为两万句预先创建两万张全尺寸位图。
- **样式首版**：字号、文字颜色、描边/背景与位置，中文和常用标点必须可用。字体分发前核对资源许可；导出前渲染若干代表性帧做“成片预览”，不能默认系统字体和 Flutter 字体在两个引擎中像素一致。ASS 高级样式已明确丢弃，不在导出时意外恢复另一套布局。
- **时间与声音**：导出固定使用视频源时间轴，不受试听倍速、暂停、当前进度或 AB 区间影响，默认输出完整视频。先将源音视频轨的起点/旋转等归一到同一时间轴，再按项目时间叠字；不得以墙钟或处理帧计数代替实际呈现时间。输出后核验音画时长、音轨存在性、方向和关键字幕帧。
- **校验**：未知时长可编辑/保存，但导出需成功探测实际媒体与输出能力；未标记时间、空句或错误范围先修正。视频外的字幕不在成片内出现，导出前展示将不出现/跨边界裁切的句数供确认；保留项目原数据，不为了导出而删除草稿行。不得把零字幕的输出当作“添加字幕成功”。
- **任务协议**：`startSubtitleVideoExport(projectId, revision, sourceHandle, targetHandle, cues, style, profile)` 返回 jobId；事件携带 jobId、阶段、已处理媒体时间/进度、状态和错误码；提供查询状态与取消。平台通道只传元数据和有界字幕数据，不传视频字节。
- **状态机**：校验 → 准备 → 编码 → 写入目标 → 校验成片 → 完成；分支为取消/失败。一次只编码一个项目，导出使用不可变快照；继续编辑产生新 revision，不改变进行中的成片，界面标明导出版本。进度未知时显示阶段，不编造百分比。
- **文件与空间**：开始前检查源授权、目标授权与预计空间。临时编码使用应用可写目录，编码完成验证后以排他创建方式写用户选择的目标；不能假设目标父目录已获授权，也不承诺目标复制是原子操作。写入/复制阶段也算导出任务，直到完整落盘才显示成功。空间不足不影响已保存的字幕项目；空间预检尚待任务服务接入。
- **取消/失败**：停止编码并释放读取/写入句柄，清理仅属于该 job 的临时文件；如外部目标已产生部分文件，尝试删除本次新建文件并报告结果，不能清理原视频或其他用户文件。建议使用新名称，避免失败覆盖既有成片。低空间、失去授权、源变化、磁盘移除、编码器错误均应给出可重试原因。
- **生命周期**：导出任务由 macOS 应用级服务持有，离开工作台或最小化窗口不取消；任务中心仍可查看/取消。退出应用需提示有未完成导出，选择继续等待或取消后退出；异常退出后标记任务中断、保留项目供重新导出，不宣称断点续编。睡眠/唤醒的行为需真机验证，不默认阻止系统睡眠。
- **实施顺序**：只在 macOS 验证最小烧录样例与关键边界，再接入完整工作台。其他桌面系统返回 unsupported；移动端不展示入口、不接入编码引擎。共享字幕模型变化仅做原有播放兼容回归，不借此扩展手机端产品范围。

## 文件、安全与保存

- macOS 使用系统文件选择器和用户选定文件的授权，不要求扩大到全部磁盘权限。新增项目文件只能写应用管理目录；成片写用户确认的位置。
- 将初稿 5 MB/5 万句的上限收紧为阶段 A 的初始预算：源文件 2 MiB、2 万句、单句 16 KiB UTF-8、解析后字幕 JSON 8 MiB；解码/解析放后台 isolate。它们是待压力验证的保护值，不是性能承诺。超过限制明确拒绝，不截断后当作成功。
- 优先 BOM 明确编码，否则严格 UTF-8；无 BOM UTF-16 需用户确认后按 LE/BE 重试，不因 UTF-8 解码失败就轮流尝试到某种编码“成功”。旧式中文编码提示转为 UTF-8，另评估解码依赖；可预览解码文本再确认替换。
- 字幕作为文本显示，不执行 HTML、ASS 命令或外部资源。错误行、异常时间与被跳过条目应有导入摘要，不能静默丢失。
- 结构硬校验：合法数字、分钟/秒范围、`0 <= start < end`、非空文本；格式严格但允许常见换行/BOM。部分条目失败需展示数量和样例，让用户明确选择“仅导入有效条目”，全失败不能覆盖现有字幕。允许重叠及相同起点，不能复用歌词要求起点严格递增的校验器。
- 视频时长属于关联校验：未知时仍可导入字幕和保存草稿，提示尚未核对范围；已知时对超出部分提示可能是不同视频版本，不自动删句。依赖时长的比例 seek 和成片导出暂不可用，直到获得有效媒体信息。
- SRT 简单格式标签与 ASS 覆盖标签必须有明确转换策略：首期仅规范化换行、去除支持识别的样式标签并提示丢失样式，未知内容不得无报告地吞掉。扩展名、声明格式与内容不一致时报告错误。
- 所有涉及 library 的写入（扫描、断点、校准、导入、项目应用、备份恢复）必须经过同一个应用层协调器，不只串行字幕保存。排队时保存变更意图，执行时合并最新状态生成快照；待确认字幕不进入其他路径的持久快照。项目内部保存则按 projectId 串行。项目应用到媒体库先保存项目快照，再校验 library 基准 revision 并写入；失败保持正式字幕原状态，项目可继续编辑，不要求两个存储分区伪装成原子事务。
- 显式保存必须接收可靠成功/失败结果，不能走吞异常的普通 `save()`。草稿防抖、串行合并，退出等待最后一次保存，失败允许重试/明确放弃；撤销历史使用增量命令或字节预算，不能为 2 万句保存 100 份完整深拷贝。初稿中发现的 Android 存储返回值问题记录为现有风险，不扩入本桌面功能的修改范围。
- 当前 library 整体存储易被大字幕放大。发布前验证多视频、大文件、连续编辑和断点保存的内存/卡顿；不得每次字幕刷新都序列化整个库。独立项目不能写入一个不受备份/删除管理的旁路文件。
- 导出前保存最新项目 revision，然后冻结快照；字幕时间不得再叠加媒体库校准、设备延迟或未确认预览。视频时间范围外的句子只影响本次渲染，不从项目永久移除。
- 不自动覆盖原字幕/视频文件；成片只能另存，输出与输入相同直接拒绝。离线处理无需上传视频。

## 验收与边界

- macOS 验证独立视频选择/取消/重新授权、字幕编码/大小限制、SRT 多行和 ASS 转纯文本提示；移动端只回归原有播放与验证新增入口不可见。
- 验证提前/延后方向、开始和结束边界、暂停定位、倍速、seek、AB、切视频竞态、重叠句与短字幕。
- 验证项目保存重启、取消恢复、失败回滚、重新扫描保留、重新导入重置、成片字幕时间与预览一致。
- 验证全屏、窄屏、控制栏隐藏时字幕仍可读；单独检查画中画，如不支持应明确提示，不能宣称与普通视频叠加层等效。
- 当前 macOS 能力表不支持 PiP，工作台首期不新增 PiP 或浮窗预览；Android 现有 PiP 不随本功能改变。导出的硬字幕已在画面中，不受外挂字幕层是否存在影响。
- 强制验证：原句 `[10s,12s)`，提前 1s 后在 `[9s,11s)` 显示；延后 1s 则 `[11s,13s)`；原句开始对齐到 11s 得到 -1000ms。进入编辑器看到 11s/13s，应用后正式时间变为 11s/13s、偏移为零，显示不得再次变到 12s/14s。
- 强制验证：视频未入库也能手动添加字幕并导出；时长未知可保存但导出需有效探测；零点/字幕空隙暂停可校准；相邻句边界不双显；同起点双语不漏句；成片不受试听 2×/AB 影响；越界字幕先报告。
- 强制验证：导入选择期间切视频/删除目标、断点保存与字幕应用并发、保存失败/取消、备份恢复后旧编辑器保存、重复导出回调、同名字幕更新与冲突草稿、应用内改名/移动前的关联保护。
- 成片验证：横竖屏/旋转、无音轨/有音轨、中文字体/多行、导出开头/中段/结尾、长视频音画同步、不同播放器播放、取消/磁盘满/目标移除/源失效、同路径拒绝、任务版本冻结与临时文件回收。
- 用既有静态检查、核心逻辑检查、平台构建和真机验证；按项目约定默认不新增前端单元测试。
