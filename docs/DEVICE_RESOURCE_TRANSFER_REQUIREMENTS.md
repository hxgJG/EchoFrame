## 1. 需求理解

让安装忆光的两台设备在不注册、不登录账号的情况下，由资源所在设备主动开启共享，另一台设备通过安全码申请连接。资源提供方核对请求设备的安全码并明确允许后，接收方可在限时会话和获批范围内自由选择、下载、保存和使用资源，不逐批重复审批。

- A 和 B 是临时角色，任何一方都可以提供或接收资源。
- A 允许 B 下载，不代表 B 同时允许 A 下载；反向传输必须单独开启和授权。
- 本期建议定义为 **按需复制资源和关联信息**，不是自动双向同步、云盘或远程播放器。
- 下载音视频会在接收设备保存一份真实文件、占用存储；提供设备的原文件不移动、不修改。
- “无需账号”不等于没有设备身份、加密或授权。

### 1.1 用户已明确的要求

1. 不需要账号。
2. A 主动开启允许其他设备下载的服务。
3. A 有安全码，B 使用它连接 A。
4. B 可以选择音乐、视频、歌词等资源，不必整库迁移。
5. 下载前必须由 A 允许一次，A 的确认界面必须显示 B 的安全码。
6. 只能共享当前 App 有权访问的资源。
7. 支持反向使用同一流程。
8. 首版只做局域网，不依赖云端。
9. A 批准一次连接，在限时连接内 B 可以自由选取下载，不采用每批清单审批或永久信任。
10. 首版支持 macOS ↔ Android、macOS ↔ macOS、Android ↔ Android。
11. A 预先选择共享资源或分类，支持一键全选，不默认开放整个媒体库。
12. 默认访问授权为 1 小时，A 授权时可以指定时间。
13. 首版先保证前台传输，不将手机后台、锁屏持续传输纳入首版交付。
14. 相关页面（包括确需使用的网页）都在 App 内展示和操作，不跳转外部浏览器完成流程。
15. 接收文件默认保存在 App 管理的“已接收”目录，自动入库，提供另行导出；接受私有目录在卸载/清除数据时可能被清理的边界，界面必须提示。
16. 首版包含音乐、视频、歌词、歌曲展示信息和可选封面；外挂字幕、字幕项目、播放列表、收藏和历史不纳入。
17. 授权时间默认 1 小时，可指定 5 分钟至 24 小时，不提供永久授权。
18. 首版同时连接一台设备、最多并行下载两个文件；相同内容跳过复制，同名不同内容保留两份；歌词覆盖与展示信息同步分别可选。
19. 已允许联网查询公开官方技术资料，不上传项目代码或媒体文件。

### 1.2 首版不解决

- 云端保存、账号体系、无人值守自动同步、远程控制播放。
- 删除同步、目录镜像、双方修改自动合并、远程改名或写入 A 的文件。
- 整机文件浏览、任意路径下载、绕过系统权限、公开下载链接或浏览器网页下载。
- 视频转码、格式转换、重新压缩音频；原始媒体按字节传输。
- 播放历史、收藏、播放列表、设备设置、密钥、应用备份和编辑草稿迁移。
- 首版跨互联网中转、后台常驻、开机自启和新增其他平台适配，除非用户选择纳入。

## 4. 产品入口与流程

### 4.1 独立入口

建议「设置 → 设备互传」，桌面可另设侧栏/菜单入口。页面包含：

- **提供资源**：共享开关、共享范围、本机设备码、当前连接码/二维码、等待审批、连接中的设备、停止共享。
- **接收资源**：附近设备、手动连接、对端资源目录、下载清单、覆盖选项。
- **传输任务**：发送/接收、数量、总大小、当前速度与进度、已完成/失败项、暂停/继续/取消。

媒体列表的多选菜单可以作为后续快捷入口，但不能替代独立页面。

**App 内闭环（用户已确认）：**

- 开启共享、展示/输入安全码、设备发现、手动连接、授权/续期、资源浏览、下载进度、冲突处理和使用说明，都在忆光 App 内完成。
- 优先沿用 Flutter 页面，不因“相关网页”而强制把已有 App 功能改成 WebView，也不新增独立网页管理端或浏览器下载入口。
- 若确实需要 HTML/网页内容，使用 App 内受控的嵌入页面，不自动打开外部浏览器、新窗口或外部应用；禁止将设备提供的任意网页/脚本作为可信控制界面加载。
- 网络传输服务提供的是受授权约束的协议接口，不要求用户复制局域网网址到浏览器。手动地址输入也是 App 内连接表单，不是打开对端网站。
- 下载始终由 App 的传输任务管理，不能转交浏览器下载；审批必须由本机可信 App 界面执行，网页不能自行模拟批准或取得任意文件访问桥接能力。
- 标准系统权限弹窗和必要的系统文件/目录选择器仍可使用，不属于外部网页；不为满足“App 内”而绕过系统授权。
- 内嵌展示不等于授权访问。原有设备身份校验、共享范围、到期和撤销规则仍全部生效，局域网核心流程不依赖在线网页。

### 4.2 已确认主流程：一次审批对应限时会话

```text
A 选择共享资源并开启服务
    ↓
B 发现/输入 A 地址，通过 A 连接码或二维码申请安全连接
    ↓
A 核对 B 设备码、连接校验信息，确认共享范围与时长
    ↓
    ├─ 拒绝 / 超时 → 不提供目录和文件正文
    └─ 允许 → 建立仅针对 B、限定范围和时长的只读会话
                    ↓
            B 浏览目录，自由选择资源和接收策略
                    ↓
            下载 → 校验 → 保存 → 入库 → 结果回执
                    ↓
            有效期内可继续选择其他获批资源，无需再次审批
```

**目录可见性的明确约定：** A 批准前，B 只能看到连接所必需的设备/协议信息，看不到媒体目录。A 一次批准后，B 可以浏览获批范围并自行下载，已在范围内的封面缩略图也可按需显示；不再新增第二次下载确认。目录只包含必要字段，不暴露本机路径。

A 的审批卡必须显示：B 自定义设备名、平台、设备安全码、用于现场比对的连接校验信息、将开放的资源类型/数量/总大小、范围详情入口、访问时长，以及“有效期内可自由浏览和下载，无需再次确认”。此时 B 尚未选下载清单，不应伪称 A 已确认具体下载内容。设备名可伪造，不作为身份凭据。不提供默认永久信任。

时长默认填入 **1 小时**，允许 A 在批准前修改。提供 15 分钟、30 分钟、1 小时、2 小时快捷项及自定义时长，并显示换算后的本地到期时间；已确认自定义范围为 5 分钟至 24 小时，不提供无限期。有效期由提供资源的一方执行，修改设备墙上时钟或恢复连接不能延长授权。

### 4.3 授权的“一次”

- 授权的是一台 B 对一个限定资源集合的限时只读访问，而非单个文件、下载清单或 HTTP 请求。正常选取、分块、重试和范围内的新任务不重复弹审批。
- 每个下载任务仍冻结资源版本和所选附件，以便校验/恢复，但不因此要求 A 逐批批准。
- A 可拒绝连接，或在批准前缩小范围、调整时长。换接收设备、超时续期、扩大当前会话的共享范围，都需要 A 明确重新授权。
- A 对获批资源作内容更新后，B 可以在有效会话内明确请求该资源的新版本；旧任务不得混合版本，新资源 ID 不自动加入旧授权。
- 取消、撤销、关闭共享、会话到期后不能继续获取新数据；已下载到 B 的数据无法远程收回。
- B 的“接收本次更新”策略与 A 的“允许发送”互相独立，A 不能强制覆盖 B 的本地数据。

## 5. 资源边界

### 5.1 可共享集合

`当前 App 正式索引/歌词库中的资源 ∩ 当前系统授权可读 ∩ 当前可见且未被排除 ∩ A 本次明确选择的共享集合`。

- 共享范围默认空，用户选歌曲、视频、歌词或批量分类/虚拟分组后才开启。
- “共享文件夹”若提供，实际是该分组内符合条件的已索引资源，不是递归开放整个系统目录。
- 开启时冻结目录范围，批准连接时记录该会话的授权范围；后续扫描新增文件不自动加入。A 缩小范围后更新目录版本，移除项的现有授权立即失效；扩大范围不能自动扩展已批准会话。
- 音视频已丢失、无权限、已隐藏、扫描排除、外置磁盘拔出、尚未下载到本机的云占位文件，都不自动对外提供。
- 待匹配歌词可以独立共享，无需 A 或 B 存在对应音频。
- 只读来源可以在有读取权限且被明确共享时发送，不需要为发送申请写源文件权限。

### 5.2 已确认的首版资源清单

| 资源 | 传输内容 | 说明 |
| --- | --- | --- |
| 音乐 | 原始音频文件、必要展示信息 | 可勾选关联歌词；不改源文件标签 |
| 视频 | 原始视频文件、必要展示信息 | 已烧录字幕属于视频画面的一部分；不触发重新导出/转码 |
| 歌词 | 正式歌词、毫秒时间、单曲校准、匹配信息和别名 | 可单首或批量，复用跨设备歌词包语义 |
| 封面 | App 已有且纳入共享范围的封面附件 | 会话获批后可用于目录预览/下载，不下载在线新封面 |
| 外挂字幕/字幕项目 | 暂不纳入首版 | “等”不等于开放所有文件；需要时补充格式、绑定、样式与草稿规则 |

不传本机绝对路径、文件夹授权书签、Content URI、设备私钥、连接令牌、设置、隐藏清单或整份 App 状态。

## 6. 安全码与连接设计要求

### 6.1 区分三种信息，避免一个短码承担所有职责

| 名称 | 用途 | 建议规则 |
| --- | --- | --- |
| 设备安全码 | 人工识别“是哪台设备”，A 审批时展示 B 的码 | 基于本次安装的设备公钥身份生成可读指纹；重装/重置身份后改变；不是密码，不能单凭它授权 |
| 本次连接码/二维码 | 让 B 找到并发起与 A 的本次连接 | A 每次开启或刷新时更新，有效期短；二维码可携带地址及高熵连接材料；连接码不在广播中公开 |
| 会话访问授权 | 真正允许浏览和下载哪些资源 | 系统内部短期凭据，绑定已验证的 B、共享会话、资源/附件范围和有效期，不展示成可转发下载链接；下载任务另外绑定内容版本 |

界面可以保留用户熟悉的“安全码”叫法，但必须解释设备识别码与本次连接码不同。B 自报一个字符串并让 A 点允许不构成可信身份校验；两端展示的校验信息必须由实际安全连接生成并相互绑定。

### 6.2 必须满足的保护边界

- 目录及传输使用经过对端身份校验的加密连接；不使用明文文件服务，不忽略所有证书错误。
- 短连接码不能直接充当唯一加密密钥。二维码外带可信信息、人工比对会话校验码或成熟的短码认证协议需在技术设计阶段选定；不自研密码学协议。
- 无法承诺“只有官方 App 二进制能访问”：第三方可能仿造协议。实际安全承诺应是 **只有经验证并获 A 授权的设备会话可以读取指定资源**，不依赖 User-Agent、隐藏 API 或 App 内固定密钥。
- 广播只暴露临时发现标识、必要设备展示名和能力，不公开安全码、目录和媒体内容。
- 只提供限定资源 ID 的只读接口。对端不能提交本机路径/URI，也不能要求服务端抓取任意 URL、执行命令、列目录、删除或覆盖文件。
- 每次请求校验授权与资源范围，不只在首次连接检查；失效授权不能通过 Range/重试继续使用。
- 重新检查文件授权和实际文件身份，处理符号链接越界、文件在审批后被替换、读写竞态及授权撤销；不能照搬仅按路径前缀匹配的判断。
- 限制连接尝试、审批频率、并发、清单大小、元数据和图片大小；拒绝异常请求，避免猜码、弹窗轰炸和耗尽内存/磁盘。
- 密钥保存在平台安全存储，普通应用备份不复制设备身份或有效授权。重置身份将使旧配对信息失效。
- 不自动开放公网、不配置路由器端口映射；网络变化时暂停并重新确认本地连接范围。

撤销只能阻止后续读取，无法撤销已经复制的文件；关闭共享也不能承诺回收系统网络缓冲中已发出的字节，界面不得作相反宣传。

## 7. 下载、保存与“同步”的语义

### 7.1 音视频

1. 提交前显示总大小、可用空间、重复项、接收目录及是否包含歌词/封面。
2. 先写 App 管理的临时区域，流式处理；大视频不得整文件通过 Dart MethodChannel 或内存中转。
3. 完成后校验实际大小和密码学摘要，再提交正式文件和本地索引；校验失败不显示成可播放的完整资源。
4. 同一内容已存在时跳过文件复制，但仍可单独接收新的歌词和展示信息。
5. 同名而内容不同不覆盖，创建新本地 ID/安全文件名，并保留各版本。不能用歌名或对端 ID 判定文件相同。
6. 接收后的资源需要在重启、重新扫描后仍然可见。必须增加可靠的接收资源索引/来源适配，不能只把文件写到某目录然后假设扫描器一定能发现。
7. 文件完成与索引提交分两步，有可恢复的本地任务记录；崩溃后可补登记/清理本任务产生的孤立临时文件，不影响用户原文件。

已确认默认保存到 App 管理的「已接收」持久目录，界面可查看位置并另行导出，不在下载时默认写公共媒体库。正式文件不能放在可被自动回收的缓存目录。Android 使用应用私有持久区域，macOS 使用沙盒内 Application Support；具体目录及索引规则见技术方案。提示用户清除应用数据会影响这些文件，需独立保存时先导出；Android 官方明确说明应用专属文件在卸载时被删除，不应把 macOS 的卸载行为一概等同。参见 [Android 应用专属存储](https://developer.android.com/training/data-storage/app-specific)。

### 7.2 歌词与展示信息

- 保留现有两个独立选项：「覆盖已有歌词，优先本次接收」和「同步歌名、艺术家、专辑」，默认开启但在下载前明示影响。
- 原始名称与别名随资源迁移；同一原文件优先按完整文件指纹识别，不因 App 内改名断开关联。
- 没有对应歌曲时存入独立歌词库，后续添加歌曲按用户此次接收策略匹配；歧义项留待手动关联。
- 单曲校准跟随歌词，全局播放设备偏移不迁移；歌词草稿/历史版本不默认发送。
- 接收新歌词不应自动删除本地旧版本，保持现有历史/撤销行为。
- 下载期间 B 修改了本地歌词或展示信息：提交时检查本地版本，发生冲突就提示或保留待处理，不用下载前的确认静默覆盖后续编辑。
- A 在批准后修改歌词或媒体：任务传输冻结版本，或者明确使旧任务失效。B 在有效会话和原获批范围内可选择重新获取新版本，无需 A 再次批准，不混合不同版本的文件与元数据。

### 7.3 中断与恢复

- 下载可暂停、取消、失败重试；局域网短断连可在有效授权内续传同一内容。
- 续传必须绑定同一资源版本/摘要、授权和接收设备；源文件变化则拒绝拼接。
- 会话关闭或授权过期后，重新连接/续期需要 A 再次批准；本地临时数据可以保留以便新授权后继续，保存期限明示。
- 到期对所有未完成下载暂停，不因为开始了下载就无限续权；提前显示剩余时间。用户在 A 续期后，同一内容可继续，已完成文件不受影响。
- 单个文件失败不伪装整批成功；展示成功、跳过、失败及待确认数量，支持只重试失败项。
- 取消时只清理该任务未完成的临时文件，已经完成的文件不自动删除。
- 接收成功回执丢失不能导致重复复制；两端按同一任务与资源版本幂等核对。

## 8. 服务生命周期及建议限制

默认关闭；不开启共享时不监听、不广播、不在后台等待连接。每次 App 重启保持关闭，历史记录不恢复下载权限。

**用户已确认首版先保证前台传输。** 两端保持 App 前台、设备唤醒完成传输，不承诺手机后台、系统睡眠或锁屏后的持续服务。不为本期额外实现常驻后台传输服务，也不能复用“已有后台音乐播放”直接宣称支持。

- 开始传输前提示双方保持 App 前台、避免锁屏；不能把 Android 的“前台服务”术语误认为本次用户确认的前台界面使用范围。
- 任一端切后台、锁屏、睡眠后若连接被挂起或中断，任务保留已完成项和可续传记录，不显示为成功，不破坏已下载数据；不保证操作系统给予退出前的保存时间，进度需持续检查点保存。
- 返回前台后重新校验连接、资源版本与剩余授权。原授权仍有效时可恢复；已过期、被撤销或 App 重启后则需 A 重新批准。切后台与返回前台不重置授权时长。
- 后续若需要后台持续传输，另行确认平台服务类型、运行时间限制、通知和省电策略，并做真机验收，不隐含在首版承诺中。

以下是产品初始建议值，均待实测调整，不作为已验证性能指标：

| 项目 | 建议初值 |
| --- | --- |
| 同时传输的对端 | 1 台；其他连接提示忙碌，不自动排成可无限堆积的审批队列 |
| 并行文件下载 | 2 个，双向并行时共享同一总上限 |
| 一批清单 | 最多 500 个逻辑资源；附属资源需显式计入字节和授权范围 |
| 等待 A 批准连接 | 2 分钟，超时拒绝；不后台无限等待 |
| 新连接码有效期 | 10 分钟；刷新阻止旧码建立新连接，停止共享才撤销所有现有授权 |
| 会话访问时限（Q5，用户已确认） | 默认 1 小时，批准时可指定时长；从 A 批准时起算，心跳、断线和新任务不重置时限 |
| 短断连重接 | 有效期内仅同一已认证 B 可恢复；主动撤销或关闭后不可恢复旧授权 |
| 连续错误连接码 | 5 次后冷却 60 秒，同时限制全局请求频率；不能只按 IP 防护 |
| 中断临时文件 | 最多保留 24 小时，提供手动清理入口并显示占用 |
| 本地任务记录 | 最多 30 天或最近 200 条；不记录安全码和令牌 |

不设未经实测的统一视频大小承诺。必须支持流式大文件、64 位长度/偏移、剩余空间检查和实际可读性判断；最低验收包含超过 512 MiB 的视频，不能沿用现有歌词匹配的音频哈希上限跳过校验。

## 9. 技术方向与备选方案

### 9.1 方案比较

| 方案 | 优点 | 代价/限制 | 建议 |
| --- | --- | --- | --- |
| App 内局域网点对点服务 | 无账号、无需云存储、与当前本地优先架构相符 | 同网仍可能被访客网络/客户端隔离/防火墙阻断；两端需同时在线 | 首版推荐 |
| 点对点为主，增加互联网发现/中转 | 可覆盖不同网络 | 服务部署、费用、滥用治理、身份验证、网络可达性与端到端保护均扩大范围 | 用户已选择不纳入首版，后续单独立项 |
| 专门部署一台常驻文件服务器 | 设备不必同时开启 App | 不对等，增加配置和运维，与“双方反之亦然”的体验不完全一致 | 不作为默认 |

### 9.2 推荐职责划分（逻辑设计，不锁定框架）

- Flutter：App 内共享范围、连接/审批、资源选择、冲突确认、进度及说明 UI；仅在有实际 HTML 内容需求时评估受控内嵌网页，不默认增加 WebView 依赖。
- 设备传输领域层：设备会话、共享快照、授权、任务状态机和重试策略，独立于播放状态。
- 平台适配：网络发现/监听、身份安全存储、系统授权文件流、接收落盘和入库；具体哪些网络职责复用 Dart，需小型原型验证后决定。
- 内容描述层：专门的可传输 Manifest，音视频、歌词、封面分别描述，不序列化整个 `MediaItem`。
- 历史与恢复：任务元数据独立分区/文件，二进制文件单独存储；不因本需求直接引入关系型数据库。

建议新增模块为 `lib/features/device_transfer/`、`lib/core/device_transfer/`、`lib/platform/device_transfer/`，以及两端原生适配。仅在接收入库和歌词应用处对接既有媒体库，不把网络请求直接堆到 `app_state.dart` 中。

### 9.3 逻辑实体与协议职责

| 实体 | 必要内容 |
| --- | --- |
| 设备身份 | 本机设备实例 ID、公钥身份、展示名、平台/协议能力；私钥不外发 |
| 共享会话 | 随机会话 ID、共享资源快照、目录版本、开启/到期/关闭状态 |
| 资源描述 | 不透明资源 ID、类型、必要显示字段、长度、内容摘要、版本、明确的附件关系 |
| 连接申请/会话授权 | 幂等申请 ID、请求设备身份、获批资源范围、创建/到期/撤销状态；目录与下载只读权限 |
| 下载任务清单 | 幂等任务 ID、资源及附件的精确版本清单；只可从有效会话范围中选取，不再弹 A 的审批 |
| 本地传输任务 | 角色、阶段、每项进度、临时文件引用、已验证内容、结果和可重试错误 |

协议职责依次为：版本协商 → 安全连接申请 → A 本机批准会话 → 受限目录分页/搜索 → B 提交范围内的下载任务 → 受限分块下载 → 完整性校验 → 结果回执。会话有效期内可以重复后半流程；另有续期/撤销/关闭。协议必须具备版本字段、幂等键、长度上限、明确错误类型及不支持版本时的友好提示。

已核对 Apple、Android、Dart/Flutter 官方文档，见独立技术方案中的来源与结论。文档支持采用系统 DNS-SD 发现、受验证的加密连接和平台文件流，但不等于项目已完成互通。配对协议/库、证书与平台密钥对接、权限拒绝处理仍需原型和两端真机验证，首版不新增后台服务。

## 10. 异常与反馈

- 找不到设备：提示检查同网/热点及系统网络权限，提供手动地址入口；不是反复要求用户输安全码。手动输入地址只解决发现问题，不能跳过对端身份校验和 A 的审批。
- 安全码错误/过期：不暴露目录，说明重试/刷新方式；不通过错误差异泄露资源是否存在。
- 对方拒绝/审批超时/忙碌：明确原因，不能显示为通用“下载失败”。
- 本地或远端无权限、磁盘空间不足、来源离线：停止对应资源，保留已成功项，不擅自申请全磁盘权限。
- 校验不一致、资源版本改变：不入库，可在有效会话内重试/重新选择版本，不播放半文件。
- 不支持的媒体格式：可以下载保存，但接收前说明本设备可能无法播放，不承诺通过传输解决解码兼容。
- 服务端停止共享：停止广播/监听及后续读取，并更新两端任务状态；重启后不恢复未到期权限。

## 11. 验收清单

### 功能闭环

- [ ] 所选平台组合双向完成：开启 → 申请连接 → 显示 B 安全码并批准限时会话 → 浏览/选资源 → 下载 → 自动入库 → 本地播放/显示歌词。
- [ ] 默认 1 小时及 A 指定时长均正确生效；两端显示一致的剩余时间，会话到期暂停，续期后可继续未完成任务。
- [ ] 会话内连续挑选多批范围内资源不再弹审批；连接到期或扩大授权范围需要 A 再次确认。
- [ ] 单首、多首、仅歌词、没有歌曲的歌词、音乐加歌词、原始视频均可按规则选择。
- [ ] 音频改名/文件改名/显示信息修改不破坏可确定的对应关系；歧义不自动猜测。
- [ ] 本地已有同内容文件不重复复制；同名不同内容保留两份；歌词和显示信息独立选择覆盖。
- [ ] 接收后断网、重启和重新扫描仍可使用，源设备关闭/删除资源不影响已完整下载的数据。

### 授权与边界

- [ ] 未开启、未完成连接校验、未批准会话、审批超时、已撤销均无法获取目录和文件正文。
- [ ] 持有 A 连接码不等于得到长期/全库权限；一个 B 的授权不能被另一个设备使用。
- [ ] 替换资源 ID、请求范围外资源、混合文件版本、重放旧授权、变造路径/URI、越界符号链接不能访问范围外文件。
- [ ] 刷新连接码与停止全部共享的效果明确不同；A 允许 B 不隐式允许反向访问。
- [ ] 隐藏/排除/失权/未索引资源及 App 私有配置不能泄露。
- [ ] 人工校验不一致时阻止继续，令牌、短码和本机路径不出现在日志或普通备份。

### 可靠性与回归

- [ ] 超过 512 MiB 的视频流式传输和完整摘要校验，无整文件内存加载。
- [ ] 断网续传、暂停/取消、空间耗尽、源文件变化、外盘移除、App 异常退出和重新审批可恢复且不会生成假成功。
- [ ] 部分成功与结果回执丢失不会重复复制或丢失原数据；只有本次任务的临时文件会被清理。
- [ ] 两端前台传输稳定；切后台/锁屏中断后返回前台可正确恢复或提示重新授权，不丢失已完成文件、不重置授权时限；不以后台继续运行作为首版验收条件。
- [ ] 完整流程和相关说明都在 App 内，不弹出外部浏览器，不要求使用网页管理端或浏览器下载；如有内嵌网页，外部跳转、非可信脚本和文件桥接访问被限制。
- [ ] 下载期间两端修改元数据/歌词能检测冲突，旧审批不覆盖后续编辑。
- [ ] 媒体扫描、音视频播放、现有系统分享、歌词导入导出及备份行为保持不变；新功能关闭时没有监听服务。
- [ ] macOS 签名/网络权限、Android 前台/后台限制按实际实现单独验证，不能以编译成功替代真机互传。

## 12. 建议实施顺序与停止条件

1. Q1–Q12 已确认，按本文件冻结首版产品范围，不继续扩大需求。
2. 官方资料已核对；进入实施时先完成平台权限、发现、加密配对和文件流的 macOS/Android 小型原型，按技术方案的门槛决定具体实现选型。
3. 实现单文件完整闭环，先验证授权边界和接收后稳定入库。
4. 增加歌词/展示信息、批量、去重、断点续传与冲突处理。
5. 进行两台真实设备双向验收，再扩展后台或跨互联网能力。

回滚只关闭传输入口/服务并使授权失效，不删除已接收文件、用户原资源或既有歌词库；旧版本不能安全读取新任务状态时不写回破坏数据。
